# 第12章 批量与批量操作

## 12.1 概述

前面几章我们操作的粒度大多是"单个实体"——`world.Add<T>(entity)`、`world.Set<T>(entity)`、`world.Destroy(entity)`。每次调用都会触发一次 Archetype 迁移：查表 → 创建/复用目标 Archetype → 拷贝组件数据 → 更新 EntityInfo。

当你需要对**一大批实体**做同样操作时，逐个调用会让迁移开销叠加成性能灾难。比如要把 10000 个 Enemy 实体都加上 `Poisoned` 组件：

```csharp
// ❌ 糟糕的做法：10000 次 Archetype 迁移
foreach (var e in enemies)
{
    world.Add<Poisoned>(e);
}
```

Arch 提供了一系列**批量 API**，能在一次调用中处理整个 `QueryDescription` 匹配的所有实体，把 10000 次迁移压缩成"按 Archetype 分组的几次大块拷贝"。本章详解这些 API 的用法、源码实现与性能对比。

> 💡 核心思想：**Archetype 级别的批量**比实体级别的批量更高效。同一个 Archetype 内的所有实体本来就在连续内存里，一次性整块拷贝远比逐个搬运快。

## 12.2 批量操作的优势

### 12.2.1 减少 Archetype 迁移次数

考虑"给所有有 `Position` 的实体加上 `Velocity`"：

| 方式 | 迁移次数 | 数据拷贝 |
|------|---------|---------|
| 逐个 `world.Add<Velocity>(e)` | N 次（每个实体一次） | N 次小拷贝 |
| `world.Add<Velocity>(in query, default)` | M 次（M = 匹配到的 Archetype 数） | M 次大块拷贝 |

如果一个 Archetype 有 1000 个实体，逐个调用要做 1000 次迁移；批量调用只做 1 次。差距可达 100~1000 倍。

### 12.2.2 利用连续内存

Archetype 内部把同类型组件连续存储在 Chunk 数组里。批量 API 用 `Archetype.Copy` 整块拷贝，CPU 缓存命中率极高，SIMD 友好。逐个调用则每次都要从 Chunk 中取出一个实体、查找新 Chunk、写入——缓存频繁失效。

### 12.2.3 减少锁与事件开销

如果启用了 `EVENTS`（见第 09 章），每个 `Add<T>` 都会派发一次 `OnComponentAdded` 事件。批量 API 在 [World.cs#L940](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L940) 中只派发**每个 Archetype 一次**（`OnComponentAdded<T>(newArchetype)`），事件订阅者可以用 Archetype 级别的批量处理替代逐实体处理。

## 12.3 批量创建 API

### 12.3.1 world.Create(Span<Entity>, Signature, amount)

最基础的批量创建，源码在 [World.cs#L1061](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L1061)：

```csharp
public void Create(Span<Entity> createdEntities, in Signature signature, int amount)
{
    var archetype = EnsureCapacity(in signature, amount);

    using var entityDataArray = Pool<EntityData>.Rent(amount);
    var entityData = entityDataArray.AsSpan();

    GetOrCreateEntitiesInternal(archetype, createdEntities, entityData, amount);
    archetype.AddAll(createdEntities, amount);
    AddEntityData(createdEntities, entityData, amount);
}
```

调用方式：

```csharp
var signature = new Signature(typeof(Position), typeof(Velocity));
Span<Entity> entities = stackalloc Entity[1000];  // 或 new Entity[1000]
world.Create(entities, in signature, 1000);

// entities[0..999] 现在都指向真实实体
foreach (var e in entities)
{
    // 可以立即 set 组件值
    world.Set(e, new Position { X = Random.Range(0, 100) });
}
```

💡 这个 API 把所有新实体写入一个 `Span<Entity>`，调用方可以拿到所有创建的实体引用。内部用 `Pool<EntityData>.Rent` 池化临时数组，零 GC。

### 12.3.2 world.Create<T>(int amount, T component)

更便捷的批量创建，源码在 [World.cs#L1084](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L1084)：

```csharp
public void Create<T>(int amount, in T? cmp = default)
{
    var archetype = EnsureCapacity<T>(amount);

    using var entityArray = Pool<Entity>.Rent(amount);
    using var entityDataArray = Pool<EntityData>.Rent(amount);
    var entities = entityArray.AsSpan();
    var entityData = entityDataArray.AsSpan();

    GetOrCreateEntitiesInternal(archetype, entities, entityData, amount);
    archetype.AddAll(entities, amount);

    // 关键：批量设置组件值，用 SetRange 一次性写入
    var firstSlot = entityData[0].Slot;
    var lastSlot = entityData[amount - 1].Slot;
    archetype.SetRange(in firstSlot, in lastSlot, cmp);

    AddEntityData(entities, entityData, amount);
}
```

调用方式：

```csharp
// 一次创建 10000 个有 Position 的实体，Position 初始化为 (0,0)
world.Create<Position>(10000, new Position { X = 0, Y = 0 });
```

🔥 性能关键在 `archetype.SetRange`——它把同一个值连续写入 Chunk 内的组件数组，相当于 `Array.Fill`，CPU 流水线友好。

### 12.3.3 world.Create<T0, T1, ...>(int amount, ...)

通过源生成器（详见 [World.CreateBulk.cs](file:///d:/Unity/Arch/Arch/src/Arch/Templates/World.CreateBulk.cs)），Arch 展开了 1~24 个泛型参数的重载，每个都遵循同样的模式：

```csharp
public void Create<T0, T1>(int amount, in T0? t0Component = default, in T1? t1Component = default)
{
    var archetype = EnsureCapacity<T0, T1>(amount);

    using var entityArray = Pool<Entity>.Rent(amount);
    using var entityDataArray = Pool<EntityData>.Rent(amount);
    var entities = entityArray.AsSpan();
    var entityData = entityDataArray.AsSpan();

    GetOrCreateEntitiesInternal(archetype, entities, entityData, amount);
    archetype.AddAll(entities, amount);

    var firstSlot = entityData[0].Slot;
    var lastSlot = entityData[amount - 1].Slot;
    archetype.SetRange<T0, T1>(in lastSlot, in firstSlot, in t0Component, in t1Component);

    AddEntityData(entities, entityData, amount);
}
```

调用：

```csharp
world.Create<Position, Velocity, Health>(
    amount: 5000,
    new Position { X = 0, Y = 0 },
    new Velocity { X = 1, Y = 0 },
    new Health { Value = 100 }
);
```

> ⚠️ 这些 `Create` 重载不返回 Entity。如果你需要拿到创建的实体引用，必须用 `world.Create(Span<Entity>, ...)` 形式。

## 12.4 批量修改 API

### 12.4.1 world.Add<T>(in QueryDescription, in T)

源码在 [World.cs#L899](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L899)，给查询匹配的所有实体添加同一个组件：

```csharp
[SkipLocalsInit]
[StructuralChange]
public void Add<T>(in QueryDescription queryDescription, in T? component = default)
{
    Span<uint> stack = stackalloc uint[BitSet.RequiredLength(ComponentRegistry.Size)];

    var query = Query(in queryDescription);
    foreach (var archetype in query.GetArchetypeIterator())
    {
        // 跳过已经有 T 的 Archetype，避免重复添加
        if (archetype.EntityCount == 0 || archetype.Has<T>())
        {
            continue;
        }

        // 计算新 Archetype 的 BitSet 并查找/创建
        archetype.BitSet.AsSpan(stack);
        var spanBitSet = new SpanBitSet(stack);
        spanBitSet.SetBit(Component<T>.ComponentType.Id);

        if (!TryGetArchetype(spanBitSet.GetHashCode(), out var newArchetype))
        {
            var newSignature = Signature.Add(archetype.Signature, Component<T>.Signature);
            newArchetype = GetOrCreate(newSignature);
        }

        // 关键：记录新 Archetype 的 lastSlot，用于后续 EntityInfo 更新
        var archetypeSlot = archetype.CurrentSlot;
        var newArchetypeLastSlot = newArchetype.CurrentSlot;
        Slot.Shift(ref newArchetypeLastSlot, newArchetype.EntitiesPerChunk);
        EntityInfo.Shift(archetype, archetypeSlot, newArchetype, newArchetypeLastSlot);

        // 整个 Archetype 的数据一次性拷贝过去
        var oldCapacity = newArchetype.EntityCapacity;
        Archetype.Copy(archetype, newArchetype);
        var lastSlot = newArchetype.CurrentSlot;
        newArchetype.SetRange(in lastSlot, in newArchetypeLastSlot, in component);
        archetype.Clear();

        Capacity += newArchetype.EntityCapacity - oldCapacity;
        OnComponentAdded<T>(newArchetype);
    }

    EntityInfo.EnsureCapacity(Capacity);
}
```

调用：

```csharp
var enemies = new QueryDescription(all: [typeof(Enemy)]);
world.Add<Poisoned>(in enemies, new Poisoned { Damage = 5, Duration = 3f });
```

💡 实现细节亮点：

1. **栈上 BitSet**：用 `stackalloc uint[]` 在栈上构建新 BitSet，避免堆分配。
2. **整 Archetype 拷贝**：`Archetype.Copy(archetype, newArchetype)` 把所有 Chunk 的所有组件数组整块拷贝过去。
3. **`SetRange` 填充新组件**：拷贝完后，新组件区域是未初始化的，`SetRange` 用同一个值批量填入。
4. **原 Archetype 清空**：`archetype.Clear()` 不释放内存，便于后续复用。
5. **EntityInfo 批量更新**：`EntityInfo.Shift` 把整批实体的 `Slot` 指针调整到新 Archetype。

### 12.4.2 world.Remove<T>(in QueryDescription)

源码在 [World.cs#L956](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L956)，逻辑与 `Add` 对称：

```csharp
[SkipLocalsInit]
[StructuralChange]
public void Remove<T>(in QueryDescription queryDescription)
{
    Span<uint> stack = stackalloc uint[BitSet.RequiredLength(ComponentRegistry.Size)];

    var query = Query(in queryDescription);
    foreach (var archetype in query.GetArchetypeIterator())
    {
        // 跳过没有 T 的 Archetype
        if (archetype.EntityCount <= 0 || !archetype.Has<T>())
        {
            continue;
        }

        // 计算"去掉 T 后"的 BitSet
        var bitSet = archetype.BitSet;
        var spanBitSet = new SpanBitSet(bitSet.AsSpan(stack));
        spanBitSet.ClearBit(Component<T>.ComponentType.Id);

        if (!TryGetArchetype(spanBitSet.GetHashCode(), out var newArchetype))
        {
            var newSignature = Signature.Remove(archetype.Signature, Component<T>.Signature);
            newArchetype = GetOrCreate(newSignature);
        }

        // 拷贝除 T 之外的所有组件
        // ...
        archetype.Clear();
        OnComponentRemoved<T>(newArchetype);
    }
}
```

调用：

```csharp
var dead = new QueryDescription(all: [typeof(Dead)]);
world.Remove<Dead>(in dead);  // 把所有 Dead 实体的 Dead 组件移除
```

### 12.4.3 world.Set<T>(in QueryDescription, in T)

源码在 [World.cs#L870](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L870)，**不是结构变更**——只是覆盖已有组件的值：

```csharp
public void Set<T>(in QueryDescription queryDescription, in T? value = default)
{
    var query = Query(in queryDescription);
    foreach (ref var chunk in query)
    {
        ref var componentFirstElement = ref chunk.GetFirst<T>();
        foreach (var index in chunk)
        {
            ref var component = ref Unsafe.Add(ref componentFirstElement, index);
            component = value;
#if EVENTS
            ref var entity = ref chunk.Entity(index);
            OnComponentSet<T>(entity);
#endif
        }
    }
}
```

调用：

```csharp
var allPositions = new QueryDescription(all: [typeof(Position)]);
world.Set(in allPositions, new Position { X = 0, Y = 0 });  // 把所有 Position 重置为 (0,0)
```

💡 `Set<T>` 没有 `[StructuralChange]` 标记，因为不涉及 Archetype 迁移——只是遍历 Chunk 数组赋值。这是唯一一个不需要结构变更的批量 API，性能极高。

### 12.4.4 多组件批量操作

源生成器为 `Add`/`Remove` 展开了多组件重载，详见 [World.AddWithQueryDescription.cs](file:///d:/Unity/Arch/Arch/src/Arch/Templates/World.AddWithQueryDescription.cs) 与 [World.RemoveWithQueryDescription.cs](file:///d:/Unity/Arch/Arch/src/Arch/Templates/World.RemoveWithQueryDescription.cs)：

```csharp
// 同时给匹配的实体添加 Position 和 Velocity
world.Add<Position, Velocity>(in query, new Position { X = 0 }, new Velocity { X = 1 });

// 同时移除 Dead 和 Poisoned
world.Remove<Dead, Poisoned>(in query);
```

注意 `Set<T>` 只支持单组件——因为不同组件在不同 Chunk 数组里，多组件 Set 没有意义。

### 12.4.5 world.Destroy(in QueryDescription)

虽然不是显式"Add/Remove/Set"，但批量销毁也是一种重要的批量操作：

```csharp
var dead = new QueryDescription(all: [typeof(Dead)]);
world.Destroy(in dead);  // 一次性销毁所有标记为 Dead 的实体
```

内部会遍历每个匹配的 Archetype，逐 Chunk 清空实体并归还可复用的 Id。

## 12.5 预留容量

### 12.5.1 为什么需要预留容量

当你创建大量实体时，Archetype 内部的 Chunk 数组会多次扩容。每次扩容：

1. 分配新数组（2 倍大小）；
2. 拷贝旧数据到新数组；
3. 释放旧数组。

如果预先知道要创建 N 个实体，可以一次性预留容量，避免反复扩容。

### 12.5.2 EnsureCapacity API

源码在 [World.cs#L613](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L613) 与 [World.cs#L633](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L633)：

```csharp
// 按 Signature 预留
public Archetype EnsureCapacity(in Signature signature, int amount);

// 按组件类型预留（内部构建 Signature）
public Archetype EnsureCapacity<T>(int amount);

// 多组件版本（源生成器展开 1~24 个泛型参数）
public Archetype EnsureCapacity<T0, T1>(int amount);
public Archetype EnsureCapacity<T0, T1, T2>(int amount);
// ...
```

调用：

```csharp
// 预计创建 10000 个 (Position, Velocity) 实体
world.EnsureCapacity<Position, Velocity>(10000);

for (int i = 0; i < 10000; i++)
{
    world.Create<Position, Velocity>(default, default);
}
```

💡 `EnsureCapacity` 返回 Archetype 引用，但大多数场景你不需要用它——内部已经把容量预分配好了。

## 12.6 性能对比：单个 vs 批量

### 12.6.1 测试场景

创建 10000 个 `(Position, Velocity)` 实体，分别用三种方式：

#### 方式 A：逐个创建

```csharp
for (int i = 0; i < 10000; i++)
{
    world.Create<Position, Velocity>(new Position { X = 0 }, new Velocity { X = 1 });
}
```

#### 方式 B：批量创建

```csharp
world.Create<Position, Velocity>(
    amount: 10000,
    new Position { X = 0 },
    new Velocity { X = 1 }
);
```

#### 方式 C：预留 + 批量

```csharp
world.EnsureCapacity<Position, Velocity>(10000);
world.Create<Position, Velocity>(
    amount: 10000,
    new Position { X = 0 },
    new Velocity { X = 1 }
);
```

### 12.6.2 预期性能（参考值，实际数值因机器而异）

| 方式 | 耗时（相对值） | GC 分配 | 说明 |
|------|---------------|---------|------|
| A 逐个创建 | 1.0x | 较多 | 10000 次 Archetype 内部扩容检查 |
| B 批量创建 | 0.2~0.3x | 极少 | 一次扩容 + 一次 `SetRange` |
| C 预留 + 批量 | 0.15~0.2x | 几乎为零 | 无扩容，纯数据写入 |

🔥 批量创建通常快 3~5 倍；加上预留容量可再快 30%。

### 12.6.3 修改操作对比

给 10000 个有 `Position` 的实体加上 `Velocity`：

```csharp
// 方式 A：逐个 Add
foreach (var e in entities)
{
    world.Add<Velocity>(e, new Velocity { X = 1 });
}

// 方式 B：批量 Add
world.Add<Velocity>(in query, new Velocity { X = 1 });
```

| 方式 | 耗时（相对值） | Archetype 迁移次数 |
|------|---------------|------------------|
| A 逐个 Add | 1.0x | 10000 |
| B 批量 Add | 0.05~0.1x | 1（假设全部在同一 Archetype） |

🔥 批量 Add 通常快 10~20 倍！迁移次数从 N 降到 M（Archetype 数）。

## 12.7 使用示例

完整示例见 `Assets/Scripts/Chapter12/BatchDemo.cs`：

```csharp
using System.Diagnostics;
using Arch.Core;
using UnityEngine;
using Debug = UnityEngine.Debug;

public class BatchDemo : MonoBehaviour
{
    private struct Position { public float X, Y; }
    private struct Velocity { public float X, Y; }
    private struct Health { public int Value; }
    private struct Poisoned { public float Damage; }
    private struct Dead { }

    private void Start()
    {
        var world = World.Create();
        var sw = Stopwatch.StartNew();

        // 1. 预留容量 + 批量创建 10000 个敌人
        world.EnsureCapacity<Position, Velocity, Health>(10000);
        world.Create<Position, Velocity, Health>(
            amount: 10000,
            new Position { X = 0, Y = 0 },
            new Velocity { X = 1, Y = 0 },
            new Health { Value = 100 }
        );
        Debug.Log($"[批量创建 10000] {sw.Elapsed.TotalMilliseconds:F2} ms");

        // 2. 批量添加 Poisoned 组件
        sw.Restart();
        var enemyQuery = new QueryDescription(all: [typeof(Position), typeof(Health)]);
        world.Add<Poisoned>(in enemyQuery, new Poisoned { Damage = 5f });
        Debug.Log($"[批量 Add<Poisoned> 10000] {sw.Elapsed.TotalMilliseconds:F2} ms");

        // 3. 把所有 Poisoned 实体的 Damage 设为 10
        sw.Restart();
        var poisonedQuery = new QueryDescription(all: [typeof(Poisoned)]);
        world.Set(in poisonedQuery, new Poisoned { Damage = 10f });
        Debug.Log($"[批量 Set<Poisoned> 10000] {sw.Elapsed.TotalMilliseconds:F2} ms");

        // 4. 模拟生命值耗尽，标记为 Dead
        // 假设全部生命值为 0
        world.Set<Health>(in enemyQuery, new Health { Value = 0 });
        world.Add<Dead>(in enemyQuery);

        // 5. 批量销毁所有 Dead 实体
        sw.Restart();
        var deadQuery = new QueryDescription(all: [typeof(Dead)]);
        world.Destroy(in deadQuery);
        Debug.Log($"[批量 Destroy 10000] {sw.Elapsed.TotalMilliseconds:F2} ms");
        Debug.Log($"剩余实体数: {world.Size}");

        World.Destroy(world);
    }
}
```

预期输出（具体数值因机器而异）：

```
[批量创建 10000] 1.2 ms
[批量 Add<Poisoned> 10000] 0.8 ms
[批量 Set<Poisoned> 10000] 0.2 ms
[批量 Destroy 10000] 0.5 ms
剩余实体数: 0
```

🔥 可以看到 `Set<T>` 是最快的——它不做结构变更，只遍历赋值。`Add<T>` 和 `Destroy` 涉及 Archetype 迁移/EntityInfo 更新，但仍比逐个操作快一个数量级。

## 12.8 注意事项与最佳实践

### 12.8.1 查询描述符的副作用

批量 `Add`/`Remove` 会**改变查询结果**。例如：

```csharp
var query = new QueryDescription(all: [typeof(Position)]);
world.Add<Velocity>(in query);
// 此刻 query 已经匹配不到原来的实体了——它们都加了 Velocity
```

如果你在同一帧里串行多个批量操作，注意查询条件的演变。建议：

- 用 `QueryDescription` 缓存字段，但理解它**捕获的是组件类型条件**，不是实体集合；
- 操作前用 `world.CountEntities(query)` 验证匹配数。

### 12.8.2 跨 Archetype 的批量

批量 API 内部 `foreach (var archetype in query.GetArchetypeIterator())` 逐个处理匹配的 Archetype。如果查询匹配 5 个 Archetype，每个有 2000 实体，总共要做 5 次迁移（而不是 1 次）。

💡 减少 Archetype 数量的方法：

- 避免动态拆分组件（用 `Tag` 组件代替分组）；
- 设计阶段就规划好组件组合；
- 必要时合并相似组件。

### 12.8.3 与并行查询的关系

⚠️ 批量 API 本身**不支持并行**——它们必须从主线程调用。但它们可以**替代** ParallelQuery + CommandBuffer 的某些场景：

| 需求 | 方案 A | 方案 B |
|------|-------|-------|
| 给 10000 实体加同一组件 | ParallelQuery + cb.Add + Playback | `world.Add<T>(in query)` ✅ |
| 给 10000 实体按条件加不同组件 | ParallelQuery + cb.Add + Playback | 无替代，必须用 A |
| 给 10000 实体的同一组件设同一值 | ParallelQuery + 直接 Set | `world.Set<T>(in query)` ✅ |
| 给 10000 实体按条件设不同值 | ParallelQuery + 直接 Set | 无替代 |

经验法则：**如果操作不依赖每个实体的具体数据，用批量 API；否则用 ParallelQuery。**

### 12.8.4 池化内存的复用

观察 `Create<T>` 内部：

```csharp
using var entityArray = Pool<Entity>.Rent(amount);
using var entityDataArray = Pool<EntityData>.Rent(amount);
```

`Pool<T>.Rent` 是 Arch 内置的数组池，`using` 语法保证作用域结束自动归还。频繁调用批量创建不会产生 GC 压力。

📖 如果你想在自己的代码里用同样的池，参考 `Arch.Core.Utils.Pool<T>`，API 与 `ArrayPool<T>` 类似但更高效。

## 12.9 本章小结

| 主题 | 关键点 |
|------|--------|
| **批量优势** | 减少 Archetype 迁移次数（N→M），利用连续内存，减少事件派发 |
| **批量创建（无返回）** | `world.Create<T>(int amount, in T)` / `world.Create<T0,T1,...>(amount, ...)` |
| **批量创建（有返回）** | `world.Create(Span<Entity>, in Signature, int amount)` |
| **批量 Add** | `world.Add<T>(in QueryDescription, in T)`，整 Archetype 拷贝 |
| **批量 Remove** | `world.Remove<T>(in QueryDescription)`，对称逻辑 |
| **批量 Set** | `world.Set<T>(in QueryDescription, in T)`，**非结构变更**，最快 |
| **多组件批量** | `Add<T0,T1,...>` / `Remove<T0,T1,...>` 支持 1~24 个组件 |
| **批量 Destroy** | `world.Destroy(in QueryDescription)` |
| **EnsureCapacity** | `EnsureCapacity<T>(int)` 预留 Archetype 容量，避免扩容 |
| **全局容量预留** | `world.EnsureCapacity(int)` 通过 DangerousWorldExtensions |
| **典型加速比** | 批量创建 3~5x；批量 Add 10~20x；批量 Set 几乎无开销 |
| **栈上 BitSet** | `stackalloc uint[]` 构建临时 BitSet，避免堆分配 |
| **替代 ParallelQuery** | 不依赖实体数据的操作首选批量 API |
| **Archetype 数影响** | 跨多 Archetype 仍需多次迁移，但远少于逐实体 |
