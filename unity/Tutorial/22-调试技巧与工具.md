# 第22章 调试技巧与工具

## 22.1 概述

ECS 框架的调试比传统 OOP 难——数据与逻辑分离后，"哪个系统改了这个组件？"这类问题需要专门工具。Arch 提供了一系列调试辅助：

1. `EntityDebugView` — IDE 中查看 Entity 内部
2. `Conditional` 属性与日志过滤
3. `DangerousEntityExtensions` — 访问内部数据结构
4. 调试 World 状态的方法
5. 性能分析工具
6. 常见调试场景
7. 自定义调试 HUD

> 💡 本章配套示例位于 `Assets/Scripts/Chapter22/DebugDemo.cs`。

## 22.2 EntityDebugView

[EntityDebugView.cs](file:///d:/Unity/Arch/Arch/src/Arch/Core/Utils/EntityDebugView.cs) 是 Arch 内置的调试代理类，绑定到 `Entity` struct 上：

```csharp
internal sealed class EntityDebugView
{
    public EntityDebugView(Entity entity)
    {
        _entity = entity;
        Components = IsAlive ? entity.GetAllComponents() : null;
    }

    public int Id { get => _entity.Id; }
    public bool IsAlive { get => _entity.IsAlive(); }
    public int Version { get => IsAlive ? _entity.Version : -1; }
    public object?[]? Components { get; }
    public World? World { get => IsAlive ? World.Worlds[_entity.WorldId] : null; }
    public Archetype? Archetype { get => IsAlive ? World.Worlds[_entity.WorldId].GetArchetype(_entity) : null; }
    public Chunk Chunk { get => IsAlive ? World.Worlds[_entity.WorldId].GetChunk(_entity) : default; }
}
```

### 22.2.1 在 VS / Rider 中查看

在断点处悬停 Entity 变量，展开后可以看到：

| 字段 | 含义 |
|------|------|
| `Id` | 实体唯一 ID（int） |
| `Version` | 版本号（销毁后递增） |
| `IsAlive` | 是否存活 |
| `Components` | 所有组件值（装箱显示） |
| `World` | 所属 World |
| `Archetype` | 所在 Archetype |
| `Chunk` | 所在 Chunk |
| `EntityInfo` | 内部 EntityData 槽位 |

🔥 这个调试视图被 `#if !PURE_ECS` 包裹（[EntityDebugView.cs#L1](file:///d:/Unity/Arch/Arch/src/Arch/Core/Utils/EntityDebugView.cs#L1)），在 PURE_ECS 模式下不可用——因为 PURE_ECS 的 Entity 没有 `WorldId` 字段。

### 22.2.2 调试小技巧

1. **条件断点**：右键断点 → 条件 → 输入 `entity.Id == 42`，只在特定实体触发
2. **日志断点**：右键断点 → 设置日志消息，不暂停程序
3. **Watch 窗口**：监视 `entity.Get<Health>().Value` 实时查看组件值

⚠️ `entity.Get<T>()` 在 PURE_ECS 模式下不可用，需要用 `world.Get<T>(entity)`。

## 22.3 Conditional 属性与日志

C# 的 `[Conditional("UNITY_EDITOR")]` 特性可以让方法在 Release 中被编译器**整体移除**——比 `if (DEBUG)` 更彻底（连参数计算都不执行）。

### 22.3.1 定义调试日志

```csharp
using System.Diagnostics;

public static class ArchDebug
{
    [Conditional("UNITY_EDITOR")]
    [Conditional("ARCH_DEBUG")]
    public static void Log(string message)
    {
        UnityEngine.Debug.Log($"[Arch] {message}");
    }

    [Conditional("UNITY_EDITOR")]
    public static void LogEntity(Entity entity, World world)
    {
        if (!entity.IsAlive())
        {
            Log($"Entity #{entity.Id} is dead");
            return;
        }
        var comps = entity.GetAllComponents();
        Log($"Entity #{entity.Id} v{entity.Version} ({comps.Length} components)");
    }
}
```

使用：

```csharp
ArchDebug.Log($"Created {count} entities");
ArchDebug.LogEntity(entity, _world);
```

🔥 在 Release 构建中（未定义 `UNITY_EDITOR` 与 `ARCH_DEBUG`），这些调用会被**编译器整体删除**——零开销。

### 22.3.2 调试 vs 性能

| 方式 | 性能影响 | 优点 |
|------|---------|------|
| `Debug.Log` | 始终执行 | 简单 |
| `[Conditional]` | Release 中零开销 | 编译期过滤 |
| `if (Debug.isDebugBuild)` | 运行时判断 | 灵活 |
| `#if DEBUG ... #endif` | 编译期 | 完全移除 |

💡 Arch 内部的 `[StructuralChange]` 特性（[StructuralChangeAttribute.cs](file:///d:/Unity/Arch/Arch/src/Arch/Core/Utils/StructuralChangeAttribute.cs)）就是类似的设计——标记结构变更操作，可被调试器拦截。

## 22.4 危险扩展方法 DangerousEntityExtensions

Arch 把"可能误用"的 API 放在独立的命名空间 `Arch.Core.Extensions.Dangerous` 下，强制开发者用 `using` 显式声明。

### 22.4.1 DangerousEntityExtensions

[DangerousEntityExtensions.cs](file:///d:/Unity/Arch/Arch/src/Arch/Core/Extensions/Dangerous/DangerousEntityExtensions.cs)：

```csharp
public static class DangerousEntityExtensions
{
    public static Entity CreateEntityStruct(int id, int world, int version)
    {
#if PURE_ECS
        return new Entity(id, 0, version);
#else
        return new Entity(id, world, version);
#endif
    }
}
```

🔥 这个方法**绕过 World 创建逻辑**，直接构造一个 Entity struct。如果传入了已销毁的 ID，你将获得一个看起来合法但实际指向错误位置的 Entity——**只有持久化/反序列化场景**才需要它。

## 22.5 调试 World 状态的方法

### 22.5.1 遍历所有 Archetype

[World.cs#L232](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L232)：

```csharp
public Archetypes Archetypes { get; }
```

`Archetypes` 是一个可枚举集合：

```csharp
public static void DumpArchetypes(World world)
{
    foreach (var archetype in world.Archetypes)
    {
        var signature = archetype.Signature;
        Console.WriteLine($"Archetype: {signature}, " +
                          $"chunks={archetype.ChunkCount}, " +
                          $"entities={archetype.EntityCount}");
    }
}
```

### 22.5.2 遍历所有 Chunk

使用 QueryDescription 获取匹配的 Chunk 列表：

```csharp
public static void DumpChunks(World world, QueryDescription query)
{
    // 先获取 Archetype 数量
    Span<Archetype> archetypes = new Archetype[16];
    world.GetArchetypes(in query, archetypes);

    foreach (var archetype in archetypes)
    {
        if (archetype == null) continue;
        foreach (var chunk in archetype.Chunks)
        {
            Console.WriteLine($"Chunk: capacity={chunk.Capacity}, " +
                              $"count={chunk.Count}");
        }
    }
}
```

📖 `World.GetArchetypes` 见 [World.cs#L472](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L472)。

### 22.5.3 统计实体数

[World.cs#L431](file:///d:/Unity/Arch/Arch/src/Arch/Core/World.cs#L431)：

```csharp
public int CountEntities(in QueryDescription queryDescription)
{
    var counter = 0;
    var query = Query(in queryDescription);
    foreach (var archetype in query.GetArchetypeIterator())
    {
        counter += archetype.EntityCount;
    }
    return counter;
}
```

使用：

```csharp
var totalQuery = new QueryDescription();  // 空描述匹配所有实体
var total = world.CountEntities(in totalQuery);
Console.WriteLine($"Total entities: {total}");
```

### 22.5.4 完整的 World 状态快照

```csharp
public static void DumpWorldState(World world)
{
    Console.WriteLine($"=== World #{world.Id} ===");
    Console.WriteLine($"Size (entities): {world.Size}");
    Console.WriteLine($"Capacity: {world.Capacity}");
    Console.WriteLine($"Archetype count: {world.Archetypes.Count}");
    Console.WriteLine();

    int idx = 0;
    foreach (var archetype in world.Archetypes)
    {
        var components = string.Join(", ", archetype.Signature.Components
            .Select(c => c.ComponentType.Name));
        Console.WriteLine($"  [{idx}] Archetype ({components})");
        Console.WriteLine($"      Chunks: {archetype.ChunkCount}");
        Console.WriteLine($"      Entities: {archetype.EntityCount}");
        Console.WriteLine($"      Per chunk: {archetype.EntitiesPerChunk}");
        idx++;
    }
}
```

🔥 把这个方法挂到 `[ContextMenu]` 上，可以在 Inspector 中右键调用：

```csharp
[ContextMenu("Dump World State")]
private void DumpState() => DumpWorldState(_world);
```

## 22.7 常见调试场景

### 22.7.1 实体泄漏（未 Dispose）

**症状**：游戏长时间运行后 FPS 下降，内存增长。

**排查**：

```csharp
private void OnGUI()
{
    GUILayout.Label($"Worlds: {World.WorldSize}");
    GUILayout.Label($"Entities: {_world?.Size}");
    GUILayout.Label($"Capacity: {_world?.Capacity}");
}
```

如果 `Entities` 持续增长不下降，说明有实体没被销毁。

**常见原因**：

- 创建实体时忘记记录引用，无法销毁
- 网络对象断线后未通知 World 销毁
- 子弹等临时实体没有过期机制

**修复**：在系统中加入过期检查：

```csharp
[Query]
public void DespawnExpired(ref Entity entity, ref Lifetime lifetime)
{
    lifetime.Remaining -= Time.deltaTime;
    if (lifetime.Remaining <= 0)
    {
        // 用 CommandBuffer 延后销毁
        _buffer.Destroy(entity);
    }
}
```

### 22.7.2 版本号错误

**症状**：访问某个 Entity 时数据错乱，或抛 `Entity is not alive` 异常。

**原因**：Entity 被销毁后，ID 被复用——你的 `Entity` 变量还持有旧 ID，但 Version 不匹配。

**排查**：

```csharp
// 检查版本
var alive = entity.IsAlive();
var storedVersion = entity.Version;
var currentVersion = World.Worlds[entity.WorldId].EntityInfo
    .GetEntityData(entity.Id).Version;
Console.WriteLine($"Alive: {alive}, Stored: {storedVersion}, Current: {currentVersion}");
```

📖 `EntityData` 包含 Version 字段，可通过 `DangerousWorldExtensions.GetEntityDataArray` 访问（[DangerousWorldExtensions.cs#L58](file:///d:/Unity/Arch/Arch/src/Arch/Core/Extensions/Dangerous/DangerousWorldExtensions.cs#L58)）。

**修复**：销毁 Entity 后立即把变量置为 `default`：

```csharp
_world.Destroy(entity);
entity = default;  // 防止后续误用
```

### 22.7.3 死循环查询

**症状**：游戏卡死，Profiler 显示某帧耗时极长。

**原因**：Query 回调中又触发了结构变更，导致 Archetype 集合被修改，迭代器混乱。

**排查**：

```csharp
// ❌ 错误示例：在 Query 中 Add 组件
_world.Query(in query, (Entity e) =>
{
    e.Add<Dead>();  // 修改 Archetype，迭代器失效
});
```

**修复**：使用 CommandBuffer：

```csharp
var buffer = new CommandBuffer();
_world.Query(in query, (Entity e) =>
{
    buffer.Add(e, new Dead());
});
buffer.Playback(_world);
```

### 22.7.4 World 未 Dispose

**症状**：Unity Editor 重启 Play 后报 `World with id 0 already exists`。

**原因**：上一次 Play 没有正确 Dispose World。

**修复**：

```csharp
private void OnApplicationQuit()
{
    _world?.Dispose();
    _world = null;
}

private void OnDestroy()
{
    // 兜底
    _world?.Dispose();
}
```

💡 可以在 `RuntimeInitializeOnLoadMethod` 中清理所有遗留 World：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
private static void ClearWorlds()
{
    foreach (var world in World.Worlds)
    {
        world?.Dispose();
    }
}
```

## 22.8 自定义调试 HUD

在 Unity Editor 中显示一个简易调试 HUD，实时监控 World 状态：

```csharp
using UnityEngine;
using Arch.Core;

public class ArchDebugHUD : MonoBehaviour
{
    public World world;
    private GUIStyle _style;
    private float _updateTimer;
    private float _fps;
    private int _lastFrame;
    private string _hudText;

    private void Awake()
    {
        _style = new GUIStyle
        {
            fontSize = 14,
            normal = { textColor = Color.green }
        };
    }

    private void Update()
    {
        _updateTimer += Time.unscaledDeltaTime;
        if (_updateTimer >= 0.5f)
        {
            _fps = 1f / Time.unscaledDeltaTime;
            _updateTimer = 0;

            if (world == null) return;
            _hudText = $"=== Arch Debug HUD ===\n" +
                       $"Worlds: {World.WorldSize}\n" +
                       $"World #{world.Id} entities: {world.Size}\n" +
                       $"Capacity: {world.Capacity}\n" +
                       $"Archetypes: {world.Archetypes.Count}\n" +
                       $"FPS: {_fps:F1}";
        }
    }

    private void OnGUI()
    {
        GUI.Label(new Rect(10, 10, 400, 200), _hudText, _style);
    }
}
```

🔥 把它挂到任意 GameObject 上，指定 `world` 字段后即可在 Game 视图左上角看到实时状态。

### 22.8.1 高级 HUD：显示 Query 匹配数

```csharp
public QueryDescription debugQuery = new QueryDescription().WithAll<Position>();

{

    var count = world.CountEntities(in debugQuery);

```

## 22.9 配套示例

本章的配套 Unity 示例代码位于 `Assets/Scripts/Chapter22/DebugDemo.cs`，包含：

- 一个 `ArchDebugHUD` MonoBehaviour
- 一个 `ArchDebug` 静态工具类（`[Conditional]` 日志）
- 一个 `WorldStateDumper`（右键调用 DumpState）
- 一个错误示范场景（演示版本号错误、World 泄漏）

```csharp
// Assets/Scripts/Chapter22/DebugDemo.cs 摘录
public class DebugDemo : MonoBehaviour
{
    private World _world;

    private void Awake()
    {
        _world = World.Create();
        for (int i = 0; i < 100; i++)
        {
            _world.Create(
                new Position { X = i, Y = 0 },
                new Health { Value = 100 });
        }
    }

    [ContextMenu("Dump World State")]
    private void DumpState()
    {
        var sb = new StringBuilder();
        sb.AppendLine($"World #{_world.Id}");
        sb.AppendLine($"  Entities: {_world.Size}");
        sb.AppendLine($"  Capacity: {_world.Capacity}");
        sb.AppendLine($"  Archetypes: {_world.Archetypes.Count}");
        foreach (var arch in _world.Archetypes)
        {
            sb.AppendLine($"    - {arch.Signature}: " +
                          $"chunks={arch.ChunkCount}, entities={arch.EntityCount}");
        }
        Debug.Log(sb.ToString());
    }

    private void OnApplicationQuit() => _world?.Dispose();
}
```

运行后：

1. Game 视图左上角显示 World 实时状态
2. Inspector 右键 → Dump World State 输出详细日志
3. Profiler 中可看到每个 Query 的耗时与 GC
